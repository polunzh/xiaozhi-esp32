# 本机小智部署安全审查

日期：2026-09-21。范围：当前 ESP32 固件、相邻 `xiaozhi-esp32-server/main/xiaozhi-server` 服务代码、本机配置和监听状态。

结论：当前部署存在已验证的认证缺口，应限制在可信、隔离的测试局域网。先修复设备身份认证与明文链路，再考虑长期运行或远程访问。此前联调配置验证了功能连通性，尚未达到安全部署要求。

## 方法与边界

- 阅读认证、OTA、视觉、音频、日志及设备工具调用代码；检查运行配置、文件权限和监听地址。
- 执行无破坏性检查：直接调用认证方法，以及向本机正在运行的 OTA 接口提交无固件操作的空对象请求。未打印或保存返回的 Token，未触发模型计费、设备升级或重启。
- 未进行依赖 CVE 扫描、压力测试、完整渗透测试、路由器公网映射检查或芯片 eFuse 核验。未发现的漏洞仍可能存在；本报告没有证明发生过入侵。
- 下述服务端路径均相对于相邻仓库的 `main/xiaozhi-server/`；固件路径相对于本仓库。

## 1. 高：WebSocket 认证与 OTA 凭据发放可绕过

证据：`core/websocket_server.py:210–233` 在客户端提供的 `device-id` 命中 `allowed_devices` 后直接放行，不验证 Token。该请求头可伪造，设备 MAC 不构成身份凭据。

`core/api/ota_handler.py:150` 起的配置请求处理未要求已有设备凭据；在 `286–290` 行向陌生设备签发有效 WebSocket Token。因此，单独删除白名单免认证分支仍会留下凭据获取路径。

实测：

| 检查 | 结果 | 验证层级 |
| --- | --- | --- |
| 使用白名单设备 ID，省略 Authorization | 放行 | 真实配置下直接调用认证方法 |
| 陌生设备 ID 请求运行中的 OTA 配置接口 | HTTP 200，返回 Token | 实际 HTTP 请求 |
| 使用服务真实认证密钥验证上述 Token | 验证通过 | 本地验证；密钥与 Token 未输出 |

影响：能够访问服务端口的客户端可绕过设备身份认证，进而使用服务资源；可能带来模型费用、资源耗尽和伪造会话。伪造一个设备连接本身并不证明能够控制真实板子。

修复：设备预置独立随机凭据，配置下发与 WebSocket 都验证该凭据；设备注册使用受限的一次性流程；移除 MAC 免认证；未知设备默认拒绝。设备 ID 仅用于标识和索引。

## 2. 高（需要链路攻击条件）：明文通信与升级信任

当前设备通过 HTTP 获取配置，通过 `ws://` 传输会话。服务绑定 Mac 的局域网地址，端口为 8000、8003；检查时 macOS 应用防火墙关闭。公网可达性尚未验证。

可处于通信路径上的攻击者可能读取、修改配置和会话，重定向设备连接。固件 `main/ota.cc:83–115` 获取远程配置，`219–245` 接受固件 URL/版本/强制升级字段，后续执行下载与 OTA。

当前构建配置显示 Secure Boot、Flash Encryption 和 NVS Encryption 未启用；这属于构建配置证据，芯片实际 eFuse 状态尚未核验。固件完整性检查不能替代发布者身份验证。

修复：部署 HTTPS/WSS 并在设备端正确校验证书，限制端口访问范围；为升级建立可信发布与签名校验流程。Secure Boot 等涉及 eFuse 的配置应单独制定恢复与密钥管理方案，避免在联调中直接烧写。

## 3. 高（需要服务端或链路被控制）：管理工具缺少执行权限区分

固件 `main/application.cc:107` 注册用户工具；`main/mcp_server.cc:124–166` 包含重启、通过 URL 升级固件等能力。`GetToolsList` 在约 `525` 行隐藏 `user_only` 工具，`DoToolCall` 从 `563` 行起按工具名执行时没有对应的用户权限校验。

因此，隐藏工具列表只能影响发现过程。掌握设备会话的服务端仍可直接调用这些管理能力。此项为静态代码结论，未执行重启或升级测试。

当前 `Intent=nointent`、外部 MCP 入口关闭，限制了当前模型直接调用工具的范围。未来开放工具后，需要同时考虑提示词注入与工具越权。

修复：把升级、重启、任意 URL 上传等管理能力从普通对话工具中隔离，在执行端校验管理授权；对模型开放明确的最小工具白名单。

## 4. 中（启用视觉模型后影响扩大）：视觉接口测试身份绕过

`core/api/vision_handler.py:37` 对 `Client-Id: web_test_client` 直接认证成功。直接调用验证方法，省略 Authorization 仍返回成功。

当前视觉模型仍为占位配置，本次没有证明可成功调用付费视觉模型。绕过分支已经存在，后续完成视觉配置会扩大影响。

修复：移除运行时测试身份绕过，所有调用方使用实际凭据；测试应通过隔离环境或测试替身实现。

## 5. 中：对话、凭据与录音留存

- 语音识别使用本地 FunASR；识别文本发送到配置的云端对话模型，回答文本发送到在线 EdgeTTS。自建服务仍有这些外部数据流。
- 当前模型服务域名为 `maas.qianwenaiapi.com`。本次未核实其运营主体和数据留存政策；接口兼容及请求成功不能证明服务商身份。
- `core/connection.py:218` 在 INFO 级别记录完整请求头，使用 Authorization 时可能把 Token 写入日志。`core/providers/asr/base.py:140,150` 记录识别文本。`config/logger.py:106` 配置日志保留 30 天，诊断异常信息也需要脱敏。
- 诊断 WAV 和包含原始 NVS 的完整 Flash 备份仍在磁盘上；抽查文件权限为 0644、所在目录 0755。路径可达的本机其他账户可能读取；备份包含原始 Wi-Fi 凭据，需要按秘密文件管理。
- 当前 `data/.config.yaml` 权限为 0600，且已被 Git 忽略，这是有效保护。正常录音删除设置无法自动覆盖单独保留的诊断录音。

修复：日志屏蔽 Authorization 等凭据，减少对话正文留存；备份和诊断文件使用 0600、私有目录使用 0700，明确清理周期；核实云服务商的数据政策。此审查没有删除备份或修改权限。

## 6. 中：资源与费用限制不足

`core/connection.py:127,160` 创建无容量上限的应用队列；`core/providers/asr/base.py` 的音频收集依赖会话/VAD 结束条件。当前配置下没有启用有效的每设备输出额度，也未看到明确的每设备连接并发和调用速率限制。

WebSocket 库有默认消息限制，但它无法覆盖累计音频、应用队列及多个会话的总消耗。认证绕过会使这些缺口更易被利用。

修复：限制录音时长、累计字节、队列长度、设备并发与调用速率，设置模型调用超时和服务商费用上限，正确取消被打断会话的后续生成任务。

## 修复顺序与自写服务建议

1. 同时修复 WebSocket、OTA 凭据发放、视觉测试绕过；覆盖未知设备拒绝、无凭据拒绝、凭据与设备绑定的负向测试。
2. 部署并验证 HTTPS/WSS，限制服务可访问范围；收紧日志、备份与诊断文件权限。
3. 明确管理工具授权，加入音频、并发和费用限制。
4. 核实云服务商，补充依赖漏洞扫描、进程最小权限运行及固件升级信任设计。

自己实现精简服务端可以减少功能和依赖面。首版建议只保留经过认证的设备配置与 WebSocket、音频收发、ASR、LLM、TTS；摄像头上传、远程管理、通用插件等能力按实际需求逐项加入。上述身份认证、传输保护、资源限制和数据留存策略应进入首版设计。

本次仅新增此审查文档，未修改运行服务、设备固件或安全配置。
