# 小米蓝牙音箱输出集成设计

状态：用户于 2026-09-21 确认继续；采用板载麦克风输入、蓝牙输出、断线回退与后台重连。

当前仓库保存的是默认关闭的实验原型，以下为目标设计；独立策略类尚未接入实际输出，专用构建变体、并发取消、协商参数校验与尾音处理仍待完成。

## 目标与已验证事实

ESP32-S31-Korvo-1 使用板载 ES8389 麦克风采音，把小智回复和提示音送到 Xiaomi Sound-1802。临时程序已完成真实蓝牙连接与播放，用户确认声音正常。

- 设备地址：通过 `CONFIG_XIAOZHI_BLUETOOTH_TARGET_ADDR` 在本地配置，仓库默认留空。
- 已验证配置：MPEG-4 AAC-LC、44.1 kHz、双声道；端点广告的码率上限为 160 kbps，编码器跟随最终协商值。
- ESP-IDF v6.1 的 A2DP 初始化是异步过程。必须先注册回调，在收到 `ESP_A2D_PROF_STATE_EVT / ESP_A2D_INIT_SUCCESS` 后注册编码端点，并检查 API 返回值。
- 参考证据：本地保留的独立蓝牙播放实验记录。

## 方案选择

推荐在现有音频服务中增加可选的蓝牙输出设备，由音频服务统一管理 PCM 播放、取消及完成状态。板级配置提供目标音箱地址；公共模块通过抽象接口工作。

仅在 ES8389 的 Write 中转发数据，改动较少，但音频服务无法了解蓝牙排队和尾音，容易提前开始收音。把完整测试程序放入板级文件会混合编解码、连接和硬件职责。这两种方案不采用。

## 首版行为

1. 增加独立的 `esp32-s31-korvo-1-bluetooth` 构建变体，保留现有硬件引脚与板型兼容标识；使用独立的构建名称。普通变体默认关闭蓝牙输出。
2. 通过配置项提供目标地址，使用者填写自己的音箱地址。首版支持已验证的 AAC 音箱；通用设备列表、配对界面和其他编码器留待后续需求。
3. 后台自动连接和有间隔地重试。连接及音频流准备成功后，于安全的播放边界切换输出，避免半句话切换设备。
4. 用户已确认：音箱未连接时使用板载扬声器；中途断开时丢弃蓝牙积压数据，后续音频转到板载输出，后台重连。
5. 使用现有音量控制，软件衰减蓝牙 PCM；不主动调高音箱自身音量。
6. 首版蓝牙输出采用轮流说话模式。由于板载 DAC 回声参考无法代表远端扬声器，蓝牙播放期间暂停语音输入及唤醒识别，保留按键打断；播放结束后恢复识别。关闭蓝牙功能的构建保留现有行为。
7. 取消播放时清空本地待编码与待发送数据，并发起蓝牙流暂停。音箱中已经接收的缓冲可能保留短暂尾音，必须实测并记录。

## 模块边界

- `main/audio/`：可选输出接口及蓝牙输出实现，负责连接状态、重采样、AAC 编码、发送节奏、断线和重试。
- `AudioService`：选择输出路径，统一播放代次、取消和完成判定；蓝牙队列未排空时不能通知播放完成。
- `Application`：通过通用音频能力/状态接口决定何时开始收音和允许唤醒；所有应用状态变更仍走主循环调度与状态机。
- 板级配置、Kconfig、CMake、`config.json`：配置功能开关、目标地址及构建变体。功能限定在具备已验证 Classic Bluetooth 支持的 ESP32-S31 路径。
- 现有 ES8389 负责麦克风及本地扬声器。保留当前工作区中的修复，不覆盖用户改动。
- 当前 `application.cc` 中每 50 个包打印一次的 `AudioProbe RX` 是临时诊断脚手架，集成完成前移除；未跟踪的安全审查文档和 Excalidraw 文件不纳入本功能提交。

## 数据与并发

Opus 解码得到的单声道 PCM 进入可选输出路径；蓝牙编码任务负责转换到 44.1 kHz 双声道，按协商的 AAC 格式发送。复用项目已有的 `esp_audio_effects` 与 `esp_audio_codec`，实现前阅读当前版本官方接口说明。

使用固定容量缓冲和预分配编码工作区。禁止蓝牙回调中重采样、编码、等待或修改应用状态；回调只传递必要的状态和事件。音频队列拥塞必须有明确、有界的处理策略，禁止无限等待和无限增长。用播放代次阻止取消前的音频在重连后继续发送。

蓝牙变体保持 `CONFIG_USE_SERVER_AEC` 关闭，因此不会向服务端声明 AEC；`RequiresHalfDuplexPlayback()` 强制 `GetDefaultListeningMode()` 使用 auto-stop，不受 `aec_mode_` 的实时模式选择影响。蓝牙路由不调用 `codec_->EnableOutput()`，本地 ES8389 的功放电源计时器只管理本地输出；现有 DACR 回声参考配置保留但在蓝牙路由下不作为有效回声参考。

当蓝牙缓冲满时，`AudioOutputTask` 在现有 `audio_queue_cv_` 上等待带超时的容量事件；蓝牙工作任务在释放自身锁后通过 `on_progress` 通知同一个条件变量，`Stop()` 和 `ResetDecoder()` 也通知它。等待被取消或超时即回退本地输出，不忙等。

播放完成包含本地队列耗尽、编码/发送完成以及远端播放延迟。优先使用音箱提供的延迟报告，并为不可用情况设置有界的保守尾音等待；计时用事件或定时器完成，不阻塞应用主循环。

## 验证与交付

- 主机测试：初始化事件顺序、断线重试退避、路由切换、播放代次取消、队列边界、延迟报告缺失时的播放完成判定。
- 构建：运行现有 Python 测试；构建蓝牙 S31、普通 S31，以及受公共音频接口影响的代表性芯片路径。
- 硬件：上电连接、实际小智回复、提示音、音量、板载采音、唤醒/VAD、按键打断、尾音后收音、音箱断电/重启重连、本地输出回退及 Wi-Fi 同时工作。
- 蓝牙路径不宣称支持基于板载参考的全双工 AEC。普通路径验证既有 AEC 行为。
- 上板前保存并校验可恢复镜像与设置。发生启动、采音或网络回归时恢复可用固件；通过验证后保留集成固件用于日常使用。
- 更新用户可见的构建和使用说明；新增或修改 README 时同时维护独立中英文版本。

## 已确认范围

断线自动回退板载扬声器并后台重连。首版蓝牙播放期间暂停唤醒、保留按键打断。Xiaomi Sound 不用作麦克风；输入继续使用板载 ES8389。
